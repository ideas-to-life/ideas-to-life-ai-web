🛰️ NVIDIA NemoClaw Hermes Cheat Sheet

Keep your self-improving Hermes sandbox resilient, updated, and extendable

Getting Started

🛰️ 5-Minute Quick Start
1. Prereqs: Docker Desktop (or Colima) installed, running, and reachable from your shell
2. Install + onboard Hermes: curl -fsSL https://www.nvidia.com/nemoclaw.sh | NEMOCLAW_AGENT=hermes bash
3. Follow the wizard: pick an inference provider/model, a sandbox name, and a network policy tier
4. Launch it: nemohermes launch my-assistant
5. Check in anytime: nemohermes my-assistant status

That's the whole loop: install once, then onboard → launch → status.
What NemoClaw + Hermes actually is

NemoClaw is NVIDIA's open reference stack for running agents safely inside an OpenShell sandbox — it handles onboarding, managed inference, network policy, integrations, snapshots, and lifecycle. Hermes is Nous Research's self-improving agent runtime that NemoClaw can run in place of its default OpenClaw agent. Together, Hermes learns your team's preferred workflows and turns repeated guidance into durable "Hermes Skills," while OpenShell enforces which tools, data, and network destinations it's allowed to touch.

The nemohermes alias

nemohermes is just nemoclaw with Hermes pre-selected as the agent. Use it for every day-to-day command instead of typing nemoclaw --agent hermes each time.

nemohermes onboard # first-time setup wizard
nemohermes my-sandbox connect # shell into a Hermes sandbox
nemohermes launch my-sandbox # connect AND start the Hermes agent
Non-interactive / scripted install

For CI or repeatable setup, skip the wizard prompts:

curl -fsSL https://www.nvidia.com/nemoclaw.sh | \
  NEMOCLAW_AGENT=hermes \
  NEMOCLAW_SANDBOX_NAME=my-assistant \
  NEMOCLAW_ACCEPT_THIRD_PARTY_SOFTWARE=1 \
  bash -s -- --local-model-runtime=vllm

No hosted inference credentials yet? Install without onboarding and run it later:

curl -fsSL https://www.nvidia.com/nemoclaw.sh | NEMOCLAW_AGENT=hermes bash -s -- --defer-onboarding
# later, once credentials are ready:
nemohermes onboard

Core Concepts

The moving pieces
  • OpenShell gateway — the host-side supervisor that owns sandbox lifecycle, credentials, and policy enforcement
  • Sandbox container — where Hermes actually runs, isolated from your host filesystem and network by default
  • policy.yaml — declares exactly which network destinations the sandbox may reach; anything else gets a 403
  • config.yaml — Hermes' own agent configuration inside the sandbox
Network policy tiers
TierWhat it allows
RestrictedBaseline only — nothing extra unless you add it
Balanced (default)Dev tooling, package installs, model downloads, one web search provider — no messaging platforms
OpenBroad access, including supported messaging & productivity integrations
PersonalUnrestricted outbound web (ports 80/443) for trusted personal use only
Hermes doesn't use slash commands

Unlike OpenClaw, Hermes has no in-chat / slash-command surface for lifecycle work. All status, recovery, policy, and inference operations happen from the host side with nemohermes <name> .... Inside the sandbox, the bundled NemoClaw plugin exposes status/environment tools and a skill-reload hook to the model itself.

What survives a rebuild

Hermes' durable state — memories, sessions, learned skills, plugins, cron jobs, scripts, logs, plans, workspace files, messaging state, and its kanban board — is backed up and restored automatically around rebuilds and recreations, as long as you let NemoClaw manage the process (don't delete containers by hand).

Common Workflows

🔁 You restarted your Mac

Docker doesn't come back on its own after a reboot, and neither does the OpenShell gateway or your sandbox — bring them up in this order:

1. Start Docker Desktop (or run `colima start`) and wait until it's fully up
2. nemohermes my-assistant status # this can recover a stopped container on its own
3. nemohermes my-assistant connect # or: nemohermes launch my-assistant

On reboot, OpenShell rotates its SSH host keys, so connect will detect the stale identity, prune the old openshell-* entries from ~/.ssh/known_hosts, and retry automatically — no need to re-run onboarding just because of a reboot.

🐳 You upgraded Docker

An ordinary Docker Desktop/Colima version bump usually needs nothing beyond restarting Docker and re-checking status:

nemohermes my-assistant status
nemohermes my-assistant recover # if status shows the gateway isn't reachable

If the installer detects your OpenShell gateway version has fallen outside the range the current NemoClaw release supports, it will back up every sandbox, retire the old gateway, and install the compatible OpenShell version automatically — confirm the prompt, or for scripted upgrades set NEMOCLAW_ACCEPT_EXPERIMENTAL_OPENSHELL_UPGRADE=1 ahead of the install command. Never delete or replace the gateway by hand outside this flow.

🔌 You want to add a new integration

Pick the right path for what you're connecting:

# MCP server (tools, data sources, APIs)
export GITHUB_MCP_TOKEN=ghp_...
nemohermes my-assistant mcp add github \
  --url https://api.githubcopilot.com/mcp/ --env GITHUB_MCP_TOKEN
unset GITHUB_MCP_TOKEN

# Messaging channel (Slack, Telegram, Discord, WhatsApp...)
nemohermes my-assistant channels add slack
nemohermes my-assistant rebuild

# Hermes-native plugin
# drop it under /sandbox/.hermes/plugins/<plugin-name>

MCP servers must be HTTPS with a publicly reachable, TLS-matching endpoint — NemoClaw enforces this so credentials are never sent in the clear. Adding a channel usually requires a sandbox rebuild to pick up the new credentials and policy preset.

✨ You want to activate a new feature or setting

Three patterns cover most cases:

# 1. Small config change with live reload
nemohermes my-assistant config set --key agents.defaults.model.primary \
  --value nvidia/nemotron --restart

# 2. Feature that needs a fresh sandbox (new agent flags, GPU passthrough, tool-disclosure mode)
nemohermes onboard --name my-assistant --recreate-sandbox --tool-disclosure direct

# 3. Custom image change (added a package, edited the managed Dockerfile)
nemohermes my-assistant rebuild

--recreate-sandbox backs up your workspace state first and restores it into the replacement automatically — but take a manual snapshot beforehand anyway if the change is significant.

Tips & Gotchas

🍎 macOS Docker Desktop socket quirks
Docker Desktop on macOS doesn't always expose /var/run/docker.sock the way Linux does. If the gateway can't reach the daemon, confirm Docker Desktop is actually running (not just installed) before assuming something is broken.
🍎 Colima's default resources are too small
Colima ships with 2 vCPU / 2 GiB by default, which isn't enough for the sandbox image build — it can silently stall onboarding with no error. Raise Colima's resources (or Docker Desktop's, under Settings → Resources) to at least 4 vCPU / 8 GiB before onboarding.
🚫 Don't manage the container with raw Docker commands
Avoid docker restart, docker rm, or docker exec directly on a NemoClaw-managed container. OpenShell tracks lifecycle state (Ready/Starting/Stopped) itself; bypassing it can strand the sandbox in a state nemohermes commands can't recover from.
🚫 Don't touch the bundled plugin path
Never remove or overwrite /opt/hermes/plugins/nemoclaw — it's the image-owned integration that gives Hermes its status tools and skill-reload hook. Add your own plugins alongside it, not over it.
🔑 MCP servers require HTTPS
If mcp add rejects a plain HTTP or local URL, that's the managed-registration boundary working as intended, not a bug — OpenShell only forwards bearer credentials over TLS to a publicly reachable, certificate-matching endpoint.
💾 Snapshot before you experiment
nemohermes <name> snapshot create takes seconds and gives you a clean rollback point before a rebuild, a policy tier change, or a new integration you haven't tested yet.
